# Logisim-evolution test vectors

WSU-COS 209 The Circuit-to-Cloud Workshop. (c) 2026 Wellspring University, Faculty of Computing.

These files check your Logisim-evolution circuits automatically (Logisim-evolution 3.8 or newer).

## How to run a test

1. Build your circuit in the `main` circuit of a `.circ` file, using **exactly** the pin labels in the table below.
   Input pins and output pins must be real Pin components with the label typed into their *Label* property
   (names are case-sensitive).
2. Choose **Simulate > Test Vector...**
3. Click **Load Vector** and pick the file for your practical.
4. Click **Run**. Every row that matches is green, a wrong row is red and shows the value your circuit gave.

The first line of each file is the list of pin names. Names ending in `[n]` are buses with n bits (set the
pin's *Data Bits* to n). Each other line is one test: inputs and expected outputs in binary, separated by spaces.
For a bus the leftmost bit is the highest bit (`A[4]` = `A3 A2 A1 A0`).

## Files and pin labels

| File | Practical | Pin labels (in file order) | Rows |
|---|---|---|---|
| `p02_gates.txt` | P2 Gates | inputs `A`, `B`; outputs `Y_NAND`, `Y_AND`, `Y_OR`, `Y_XOR` (four separate output pins) | 4 |
| `p02_xor3.txt` | P2 Gates | inputs `A`, `B`, `C`; output `Y` (1 when an odd number of inputs are 1) | 8 |
| `p03_prime_digit.txt` | P3 K-maps | inputs `D`, `C`, `B`, `A` (D = most significant); output `F` (digits 0 to 9 only; 10 to 15 are don't-care and not tested) | 10 |
| `p04_full_adder.txt` | P4 Adders | inputs `A`, `B`, `Cin`; outputs `S`, `Cout` | 8 |
| `p04_adder4.txt` | P4 Adders | inputs `A[4]`, `B[4]`, `Cin`; outputs `S[4]`, `Cout` (all 512 combinations) | 512 |
| `p05_decoder.txt` | P5 Decoders | inputs `A2`, `A1`, `A0`; output `Y[8]` = `Y7 Y6 Y5 Y4 Y3 Y2 Y1 Y0`, **active-low** (input 3 gives `11110111`) | 8 |

There is no vector file for the flip-flop practical (P6): the test vector tool only handles circuits whose
outputs depend on the current inputs, not on earlier clock edges.

## Tips

- A test fails on "Pin not found": the label is misspelled or on the wrong kind of pin (an input labelled as output).
- A bus pin needs a splitter to connect single wires: with `A[4]` use a 4-bit splitter and number the wires
  so that `A0` is the lowest bit.
- The files are generated by `gen_vectors.py` (kept in the instructor repository), so they are exact.
